## Ideas swept
1. **Plan, then apply only that plan, then read back.** `Host::plan` is inert and lists changes (secrets by name only); `apply` runs only the plan that was shown (approval by the plan's digest) and returns success only when the target's own state, read back afterwards, matches.
2. **One contract, many host adapters, proven by a conformance suite.** Cloudflare, Render and local adapters implement `Target`; `conformance::run` fails an adapter that acts during a plan, reports success without acting, leaks a secret, overwrites a foreign app, or does not error on an unsupported operation; an operation not yet proven against a real account is `Unverified` and refused until the caller opts in.
3. **Automatic certificate issuance and renewal for a locally served site** (through WebServAnt; opt-in by `ACME_CONTACT`; staging authority by default; `check_reachable` before a real run).
4. **TLS status read back by a real handshake** (served certificate's expiry, issuer, names, and how the last renewal ended) and, on Cloudflare, from the zone's certificate packs.
5. **Secrets pushed at deploy with names only in the plan, and a secret that must be absent is deleted** (`DeleteSecret`); a secret value never reaches a log, an error or `Debug`.
6. **An operating-system service definition (systemd unit, Windows service) generated from a spec, every value checked and quoted, shown, and installed only with the digest of exactly that text.**
7. **Probe whether the app is already on the host, then choose a fresh deploy or a reconfigure** (the plan's observed state).
8. **Rollback to the previously live version, with what happens to data stated before apply** (`Restore`; rollback never touches data).
9. **Static hosting and TLS termination on the local machine:** serve a folder, bind to loopback unless opted out, forward one path prefix to an upstream.
10. **Attach a custom domain to a Cloudflare Worker without overwriting a hostname another Worker holds** (look first, then attach).
